# ADR-0001: Java 17 и Swing для десктопного клиента

* **Статус:** Принято
* **Дата:** 2026-10-20
* **Автор:** Ефлаков Д.Д.
* **Связанные требования:** `NFR-001`, `NFR-004`, `NFR-005`, `NFR-009`, `NFR-010`

## Контекст и постановка задачи
Необходимо выбрать технологический стек и UI-фреймворк для разработки однопользовательской десктопной игры-кликера **StarForge Clicker**, обеспечивающий кроссплатформенный запуск (Windows, Linux, macOS), малое потребление оперативной памяти (до 512 МБ), быстрый старт (≤ 3 с) и поставку в виде одного исполняемого файла без внешних зависимостей.

## Рассмотренные варианты
1. **Java 17 (LTS) + стандартная библиотека AWT/Swing**
2. **Java 17 + JavaFX**
3. **Electron / TypeScript (веб-обёртка)**

## Принятое решение
Выбран вариант **1: Java 17 (LTS) и библиотека Swing**.

### Обоснование
* **Отсутствие внешних зависимостей:** Swing входит в стандартную поставку JDK (`java.desktop`), что позволяет собирать лёгкий самодостаточный `starforge-clicker.jar` размером менее 100 КБ без необходимости бандлить модули JavaFX под каждую ОС или тянуть Chromium (Electron).
* **Низкое потребление ресурсов:** приложение на Swing расходует менее 100–150 МБ ОЗУ и запускается за ~1 секунду, с большим запасом выполняя `NFR-001` и `NFR-004`.
* **Предсказуемая модель отрисовки:** компоненты `JFrame`, `JPanel`, `JButton` и кастомная отрисовка `Graphics2D` полностью закрывают потребности 2D-интерфейса кликера, представленного на макетах SRS.

## Последствия
* **Положительные:** простая сборка через Maven, высокая скорость компиляции и прогона тестов в GitHub Actions, идентичная работа на Windows, Linux и macOS.
* **Отрицательные:** стандартные контролы Swing требуют явной настройки цветов, отступов и шрифтов для соответствия тёмной космической теме.
